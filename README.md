# Algorithmicon

**Graph algorithms, one decision at a time.**

Algorithmicon is an interactive library of 18 graph algorithms. Build a graph, pick an algorithm and step through every decision it makes, with the reason spelled out at each step. You can play, pause, rewind and scrub through a run like a video.

It is written in plain TypeScript with no frameworks and no runtime dependencies, and it runs entirely in the browser.

## What it does

- **Step-by-step runs.** Every step highlights the vertices and edges involved and explains in a sentence what the algorithm just decided and why.
- **A working table.** Distances, queues, matchings or components update next to the graph as the run advances.
- **Your own graphs.** Load the built-in example, generate a random graph, or type an edge list such as `A B 4`. Drag vertices to rearrange the drawing.
- **A reference for each algorithm.** How it works in four stops, its time complexity, the kind of graph it expects and when to choose it.
- **Light and dark themes.** Follows your system setting, with a toggle to override it.
- **Works on phones** and with the keyboard (left and right arrows step through a run).

## The algorithms

The algorithms are grouped into six lines, like a transit map.

| Line | Algorithms |
|---|---|
| Traversal | Breadth-first search, Depth-first search |
| Shortest paths | Dijkstra, Bellman-Ford, Floyd-Warshall, A* search |
| Spanning trees | Kruskal, Prim, Borůvka |
| Order and components | Topological sort (Kahn), Tarjan, Kosaraju |
| Flow and matching | Ford-Fulkerson (Edmonds-Karp), Dinic, Hopcroft-Karp |
| Tours and cycles | Fleury, Hierholzer, Cycle detection |

The same graph is read differently by each algorithm: as directed or undirected, with weights as lengths, costs or capacities. The workbench says which reading is in use.

A few behaviours worth knowing:

- **Dijkstra and A\*** refuse a graph with a negative weight and point you to Bellman-Ford.
- **Bellman-Ford and Floyd-Warshall** detect negative cycles. There is a ready-made example to try.
- **A\*** estimates the remaining distance as the straight line on the drawing, so dragging a vertex changes the run.
- **Hopcroft-Karp** needs a bipartite graph and shows the offending edge if it is not.
- **Kosaraju** really does turn the arrows around for its second pass.

## Getting started

You need [Node.js](https://nodejs.org) 18 or newer.

```bash
npm install
```

```bash
npm run build
```

```bash
npm run serve
```

Then open <http://localhost:4173>.

| Command | What it does |
|---|---|
| `npm run build` | Compiles `src/*.ts` into `public/js/` |
| `npm start` | Recompiles on every change (`tsc --watch`) |
| `npm run serve` | Serves `public/` locally with security headers |

The compiled files in `public/js/` are committed, so the `public/` folder can also be hosted as it is on any static host.

## Edge list format

One edge per line: from, to and an optional whole-number weight.

```
A B 6
A C 4
C B -2
```

- Vertices are the letters `A` to `N` (up to 14).
- Weights range from -99 to 99 and default to 1.
- One edge per pair of vertices, and no loops.

## Security

The page is built to run under a strict Content-Security-Policy.

- `default-src 'none'`, with scripts and styles allowed only from the site itself.
- No inline scripts, inline styles or event-handler attributes.
- No third-party requests: no CDNs, web fonts, analytics or cookies.
- Everything you type goes through a strict parser with size limits and is only ever written to the page as text, never as markup.
- Nothing leaves your browser. The only thing stored is your light or dark choice, in `localStorage`.

`server.js` adds the headers a `<meta>` tag cannot set (`frame-ancestors`, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` and others), accepts only `GET` and `HEAD`, blocks path traversal and listens on `127.0.0.1` only. If you deploy elsewhere, configure the same headers on your host.

## How it works

Every algorithm is a function that takes a graph and returns a list of steps. A step holds a sentence of explanation plus the state of each vertex and edge, their labels and an optional table. The page only knows how to draw a step, so playback, rewinding and scrubbing work the same way for all of them.

### Adding an algorithm

1. Write a function that returns `Step[]`, using `StepRecorder` from `src/module.ts`.
2. Add its id to the `AlgoId` type in `src/module.ts`.
3. Describe it in `ALGORITHMS` in `src/catalog.ts`. The pickers, the explanation panel and the overview table are generated from that list.
4. Give it an example graph in `EXAMPLES` in `src/graph-builder.ts`.
5. If it lives in a new file, add a `<script>` tag for it in `public/algorithmicon.html`, then run `npm run build`.

The source files are global scripts without `import` or `export`, so they must be loaded in dependency order: `module.js` first and `app.js` last.
